- 主要包含服务：
	-  [Security   安全](https://docs.openstack.org/install-guide/environment-security.html)
		- OpenStack 服务支持多种安全方法，包括密码、策略和加密。此外，数据库服务器和消息代理等支持服务也支持密码安全。
	- [Host networking   主机联网](https://docs.openstack.org/install-guide/environment-networking.html)
		- 在您选择的架构的每个节点上安装操作系统后，您必须配置网络接口。我们建议您禁用所有自动网络管理工具，并手动编辑适用于您发行版的相应配置文件。
	- [Network Time Protocol (NTP)  网络时间协议（NTP）](https://docs.openstack.org/install-guide/environment-ntp.html)
		- 为了确保节点间服务同步的正确性，您可以安装 Chrony，它是 [NTP](https://docs.openstack.org/install-guide/common/glossary.html#term-Network-Time-Protocol-NTP) 的一种实现。我们建议您将控制节点配置为引用更精确（较低层级）的服务器，并将其他节点配置为引用控制节点。
	- [OpenStack packages   OpenStack 包](https://docs.openstack.org/install-guide/environment-packages.html)
		- 由于发布计划各不相同，OpenStack 发行版可能通过发行版本身或其他方式发布软件包。 OpenStack 软件包的设置需要在所有节点上完成：控制器节点、计算节点和块存储节点。您的主机必须包含适用于您的发行版的最新基础安装包版本。禁用或移除任何自动更新服务，因为它们可能会影响您的 OpenStack 环境。
	- [SQL database   SQL 数据库](https://docs.openstack.org/install-guide/environment-sql-database.html)
		- 大多数 OpenStack 服务都使用 SQL 数据库来存储信息。 数据库通常运行在控制器节点上。此过程中的步骤如下： 指南会根据发行版使用 MariaDB 或 MySQL。OpenStack 服务还支持其他 SQL 数据库，包括 [PostgreSQL](https://www.postgresql.org/) 。
	- [Message queue   消息队列](https://docs.openstack.org/install-guide/environment-messaging.html)
		- OpenStack 使用[消息队列](https://docs.openstack.org/install-guide/common/glossary.html#term-message-queue)来协调服务之间的操作和状态信息。消息队列服务通常运行在控制器节点上。OpenStack 支持多种消息队列服务，包括 [RabbitMQ](https://www.rabbitmq.com/) 和 [Qpid](https://qpid.apache.org/) 。然而，大多数打包 OpenStack 的发行版都支持特定的消息队列服务。本指南使用 RabbitMQ 消息队列服务，因为大多数发行版都支持它。如果您希望使用其他消息队列服务，请参阅相应的文档。
	- [Memcached](https://docs.openstack.org/install-guide/environment-memcached.html)
		- Memcached 是一个高性能的分布式内存对象缓存系统。简单来说，它的核心作用是通过在内存中缓存数据来减少数据库的查询压力，从而提升应用程序的响应速度。身份服务的认证机制使用 Memcached 缓存令牌。Memcached 服务通常运行在控制器节点上。对于生产环境部署，我们建议结合使用防火墙、身份验证和加密来确保其安全。
	- [Etcd](https://docs.openstack.org/install-guide/environment-etcd.html)
		- OpenStack 服务可以使用 Etcd，这是一个分布式可靠的键值存储，用于分布式键锁定、存储配置、跟踪服务存活状态等场景。
