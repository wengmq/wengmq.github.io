## 逻辑架构

- OpenStack 由多个独立部分组成，这些部分被称为 OpenStack 服务。所有服务都通过一个通用的身份服务进行身份验证。各个服务之间通过公共 API 进行交互，除非需要使用特权管理员命令。
- OpenStack 服务内部由多个进程组成。所有服务至少包含一个 API 进程，该进程监听 API 请求，对其进行预处理，然后将其传递给服务的其他部分。除身份服务外，实际工作由不同的进程完成。
- 同一服务的不同进程之间通过 AMQP 消息代理进行通信。服务的状态存储在数据库中。在部署和配置 OpenStack 云时，您可以从多种消息代理和数据库解决方案中进行选择，例如 RabbitMQ、MySQL、MariaDB 和 SQLite。
- 用户可以通过 Horizo​​n Dashboard 实现的基于 Web 的用户界面、 [命令行客户端](https://docs.openstack.org/cli-reference/)以及通过浏览器插件或 **curl** 等工具发出 API 请求来访问 OpenStack。对于应用程序， [有多种 SDK 可供](https://developer.openstack.org/#sdk)选择。 均可使用。最终，所有这些访问方法都会发出 REST API 调用。 到各种 OpenStack 服务。
