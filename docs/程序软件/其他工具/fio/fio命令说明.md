
**fio (Flexible I/O Tester)** 是 Linux 系统下最强大、最灵活的磁盘 I/O 性能基准测试工具。它可以模拟各种 I/O 负载（如顺序读写、随机读写、不同的块大小、不同的队列深度等），是存储工程师和运维人员评估硬盘（SSD/HDD）、RAID 卡或云存储性能的首选工具。

以下是关于 `fio` 的详细介绍、参数解析及常用测试场景。

---

### 一、 核心参数详解

`fio` 的参数非常多，通常分为命令行模式和配置文件模式。以下是决定测试结果的关键参数：

#### 1. I/O 模式与读写策略

- **`-rw` / `--rw` (Read/Write pattern):** 定义测试的 I/O 类型。
    
    - `read`: 顺序读
        
    - `write`: 顺序写
        
    - `randread`: 随机读
        
    - `randwrite`: 随机写
        
    - `rw` / `readwrite`: 混合顺序读写
        
    - `randrw`: 混合随机读写
        
- **`-rwmixread`:** 混合读写模式下，读操作占用的百分比（例如 `70` 表示 70% 读，30% 写）。
    
- **`-bs` (Block Size):** 单次 I/O 的块大小。
    
    - **4k**: 测 IOPS（每秒操作数）的标准大小，常用于模拟数据库、小文件读写。
        
    - **1m / 128k**: 测带宽（Throughput/BW）的标准大小，常用于模拟视频流、大文件拷贝。
        

#### 2. I/O 引擎与深度

- **`-ioengine`:** 定义 I/O 引擎，这是影响性能测试准确性的关键。
    
    - `libaio`: **最常用**。Linux 原生异步 I/O，是测试 SSD/NVMe 性能的标准引擎。
        
    - `sync`: 同步 I/O，通常用于模拟普通应用程序的标准 `read/write` 调用。
        
    - `mmap`: 内存映射 I/O。
        
- **`-iodepth`:** 队列深度（Queue Depth）。
    
    - 表示在这个 job 中，同时“在飞（in-flight）”的 I/O 请求数量。
        
    - 测试 SSD 极限性能时，通常设置较高（如 32, 64, 128）以压榨硬件性能。
        
    - 模拟单线程应用时，通常设为 1。
        
- **`-direct`:** 是否绕过操作系统缓存（Page Cache）。
    
    - `1` (True): **强烈建议**。直接测试磁盘物理性能，数据不经过 RAM 缓存。
        
    - `0` (False): 测试经过文件系统缓存后的性能。
        

#### 3. 测试目标与时间

- **`-filename`:** 指定测试的文件或设备路径。
    
    - 可以是文件路径（如 `/data/testfile`）。
        
    - 可以是裸设备（如 `/dev/sdb`）。**警告：对裸设备进行写测试会覆盖数据！**
        
- **`-size`:** 测试的数据总量（如 `10G`）。
    
- **`-numjobs`:** 并发线程/进程数。
    
- **`-runtime`:** 测试运行的时间（秒）。
    
- **`-time_based`:** 如果设置了此参数，即使 `size` 指定的数据量读写完了，也会循环重复直到达到 `runtime` 设定的时间。这对于长时间稳定性测试很有用。


## 二、 如何看懂 Fio 输出结果

运行结束后，`fio` 会输出大量数据，只需关注以下 3 个核心指标：

1. **IOPS (Input/Output Operations Per Second):**
    
    - 在输出中寻找：`IOPS=145k` 或 `iops: min=..., max=...`
        
    - 意义：每秒处理的读写次数，数值越大越好（主要用于衡量随机读写性能）。
        
2. **BW (Bandwidth):**
    
    - 在输出中寻找：`BW=566MiB/s`
        
    - 意义：吞吐量，数值越大越好（主要用于衡量顺序读写性能）。
        
3. **Lat (Latency):**
    
    - 在输出中寻找 `clat` (Completion Latency) 部分。
        
    - **slat** (Submission Latency): 提交耗时（CPU 相关）。
        
    - **clat** (Completion Latency): 完成耗时（磁盘真正的响应时间）。**重点看这个！**
        
    - **lat**: 总延迟 (`slat` + `clat`)。
        
    - 关注 **Percentiles** (百分位)：
        
        - `95.00th`: 95% 的请求都在这个时间内完成。
            
        - `99.00th` / `99.99th`: 长尾延迟，反映磁盘性能的稳定性（是否有卡顿）。
