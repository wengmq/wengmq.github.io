## 配置

你遇到的这个问题在云服务器多网卡场景中非常经典。目前两张网卡在同一个子网下，且都拥有默认路由（`metric 100`）。当外部 ping 你的第二张网卡（156.246.18.79 -> 192.168.2.141）时，请求虽然从 `eth1` 进来了，但系统回复时，**会根据主路由表（main）匹配到 `eth0` 的默认路由，导致回程数据包从 `eth0` 发出**。这种“非对称路由”会被云厂商的底层 VPC 网络防欺骗机制拦截，导致 ping 不通。

为了解决这个问题，我们需要配置**策略路由（Policy-Based Routing, PBR）**，实现“从哪个网卡进来的流量，就从哪个网卡回去”。

以下是具体的操作步骤，分为**临时测试**和**永久固化**两部分。建议先用命令临时测试，确认无误后再修改配置文件。

### 第一步：关闭严格的反向路由过滤 (rp_filter)

Linux 内核默认开启了严格的反向路径过滤（`rp_filter=1`），在非对称路由产生时会直接丢弃数据包。我们需要将其改为松散模式（`2`）或关闭（`0`）。

临时生效（立即执行）：

Bash

```
sudo sysctl -w net.ipv4.conf.all.rp_filter=2
sudo sysctl -w net.ipv4.conf.default.rp_filter=2
sudo sysctl -w net.ipv4.conf.eth0.rp_filter=2
sudo sysctl -w net.ipv4.conf.eth1.rp_filter=2
```

永久生效（写入配置文件）：

Bash

```
echo "net.ipv4.conf.all.rp_filter=2" | sudo tee -a /etc/sysctl.d/99-custom-networking.conf
echo "net.ipv4.conf.default.rp_filter=2" | sudo tee -a /etc/sysctl.d/99-custom-networking.conf
echo "net.ipv4.conf.eth0.rp_filter=2" | sudo tee -a /etc/sysctl.d/99-custom-networking.conf
echo "net.ipv4.conf.eth1.rp_filter=2" | sudo tee -a /etc/sysctl.d/99-custom-networking.conf
sudo sysctl -p /etc/sysctl.d/99-custom-networking.conf
```

### 第二步：临时配置策略路由（命令行验证）

我们先用 `ip` 命令实时注入规则，这不会断开你当前在 `eth0` 上的 SSH 连接。

**1. 为 eth0 创建路由表和规则（表号 100）：**

Bash

```
# 在表 100 中添加默认路由指向网关
sudo ip route add default via 192.168.2.1 dev eth0 table 100
# 规定源地址是 192.168.2.47 的数据包，走表 100
sudo ip rule add from 192.168.2.47 lookup 100
```

**2. 为 eth1 创建路由表和规则（表号 101）：**

Bash

```
# 在表 101 中添加默认路由指向网关
sudo ip route add default via 192.168.2.1 dev eth1 table 101
# 规定源地址是 192.168.2.141 的数据包，走表 101
sudo ip rule add from 192.168.2.141 lookup 101
```

执行完上述命令后，你可以从外部分别 `ping 156.246.18.104` 和 `ping 156.246.18.79`。此时两个公网 IP 应该都可以正常通信了。

_(注：如果重启服务器，上述 `ip` 命令会失效，请确认没问题后继续第三步)_

### 第三步：永久配置策略路由 (Ubuntu 24.04 Netplan)

Ubuntu 24.04 使用 Netplan 管理网络。你需要修改 `/etc/netplan/` 目录下的配置文件（通常是 `50-cloud-init.yaml` 或类似的名称）。

**1. 备份原配置（非常重要）：**

Bash

```
sudo cp /etc/netplan/50-cloud-init.yaml /etc/netplan/50-cloud-init.yaml.bak
```

**2. 修改配置文件：** 编辑该 YAML 文件，添加 `routing-policy` 和 `routes` 字段。为了防止主路由表中出现两个相同优先级的默认路由冲突，我们把 `eth1` 的 DHCP 默认路由优先级（metric）调低。

修改后的内容应当类似如下结构（请注意 YAML 的空格缩进，不能用 Tab）：

YAML

```
network:
  version: 2
  ethernets:
    eth0:
      dhcp4: true
      dhcp4-overrides:
        route-metric: 100
      # 策略路由规则
      routing-policy:
        - from: 192.168.2.47
          table: 100
      # 独立的路由表
      routes:
        - to: default
          via: 192.168.2.1
          table: 100
          
    eth1:
      dhcp4: true
      dhcp4-overrides:
        route-metric: 200 # 调低 eth1 在主路由表中的优先级
      # 策略路由规则
      routing-policy:
        - from: 192.168.2.141
          table: 101
      # 独立的路由表
      routes:
        - to: default
          via: 192.168.2.1
          table: 101
```

**3. 应用配置：**

Bash

```
sudo netplan try    # 建议先用 try 测试，如果有语法错误会在 120 秒后自动回滚
# 如果提示配置正确且没断网，按 ENTER 确认。或者直接使用：
sudo netplan apply
```

配置完成后，系统每次重启都会自动加载这套策略路由，保证两个浮动 IP 的入站请求都能从正确的网卡原路返回。
